# 消息体验验收

本文件是消息适配器、插件与订单通知的验收标准，不是要求模型手工模拟这些能力。仅在相关开发、故障或升级验收时读取。配置正确和单元测试通过都不等于客户端已验证。

## 飞书

1. 收到可执行消息后及时建立真实任务关联的进度卡，保持同一 message/card 标识。引用历史消息时仍在原群直接答复，不自动创建话题；多账号使用收到消息的机器人和租户。
2. 工具调用与简短进度位于正文之前，保留最近六条，按新增事件滚动；已有文字不清空重放。模型文字按增量呈现，避免全卡反复替换导致闪烁。活动指示仅在任务确实运行时显示，不伪造推理文字。
3. 耗时、压缩、自我改进、工具等待和可恢复告警进入同一卡片，不另发聊天消息。进度区不使用代码块，不把完整日志或隐藏思维链放进正文。
4. 最终化时移除临时进度，只保留最终正文和底栏。底栏按实际用量显示耗时、输入/输出、缓存、上下文和模型；区分本轮与累计口径，无数据就省略或标未知，不填假值，也不强行把异常比例截为 100%。
5. typing/在做了 从开始维持到必需工作与最终发送结束。仅成功终态转 DONE；调用结束、流断开、卡片出现、消息发送成功均不能独立代表任务成功。失败清 typing 并用 CrossMark，中断/取消用 BOMB；不得在错误正文送达后补 DONE。待用户输入应清 typing 并准确表达等待，不能将未完成业务标为成功。
6. 卡片正文不额外加“在做了”“完成”或 done 标签。飞书接口重试必须保留关联与去重，finalize 不另造重复答案。

## 微信与瑞幸

- 普通请求由处理生命周期立即发一次“已收到，思考中”；斜杠命令走命令回复，不增加确认。一个适配器负责确认，插件不能再补第二次。
- 一个回答阶段合并为一条正文，禁止转发模型调用、工具返回或 token 增量；不因异步回调重复发送。任务或阶段结束及时清 typing。错误必须可见，不能用“合并”把错误吞掉。
- 瑞幸只在点单相关任务读取 luckin-cli-ordering；模型理解门店、商品和规格，实时 CLI 预览确认价格。不要绕过模型，不重复全量查店查商品，也不在用户点单时改代码、skill 或记忆。
- 先发完整预览；确认未变的预览后只创建一次订单。创建结果不确定先查询已有订单，不盲重试。随后合并待支付说明、金额和原生二维码；不重复门店或订单号。
- 待支付、付款成功、制作中、可取餐是不同业务阶段，真实变化应分别且只通知一次。可取餐消息同时含取餐码和二维码；同一阶段不要拆成数条文字。优先使用适配器支持的文字加图片原生载荷，不能伪称平台不支持而退化。
- 发送失败保留待投递状态，重发原二维码，不重建订单。取消实际订单必须有用户授权；平台未支付超时与代理主动取消要区分，沿用 skill 已明确的期限与通知约定，不杜撰状态。

## 验收记录

覆盖普通问答、多工具长任务、真实失败/中断、引用回复和两账号路由；微信还测单次确认、合并正文、typing 清除及二维码重试。订单副作用用隔离样例或测试替身验证；真实购买需用户授权。

记录关联消息标识、事件顺序、发送/更新次数与终态，不记录密钥。客户端动效、反复刷卡和二维码可见性必须看真实客户端或明确报告未验证。不能用修改这份文档代替修复实现。
