# Hermes 升级与重启守则

更新于 2026-09-05。仅在维护时读取；这是操作与验收约定，不保证任何未来版本必定无回归。

## 先查现场

- 记录实际代码路径、版本/commit、分支、git 状态、监督进程及 gateway 子进程；配置与日志须脱敏。核对当前 /update 实现与最近原始回执，不照抄旧日期的命令。
- 明确升级范围和用户授权，检查其它会话、上传和未完成订单。会中发起的升级/重启须由监督进程接管，不能在将被终止的 gateway 子进程里循环自救。
- 只保存本次可能覆盖的配置、规则和差异，备份限量、含密钥的只留本地。当前使用已提交补丁的 local/hermes-experience 分支；不为升级先制造脏工作区，也不把旧归档补丁无条件重套到新版本。

## 执行与恢复

- 优先使用当前安装版本支持的官方升级入口和现有 CLI 更新集成。冲突先保留现场，审阅 upstream 与本地差异后最小化整合；不能用 hard reset、清 stash 或覆写源码掩盖失败。
- CLI 清单以已安装和实际维护的清单为准。Lark CLI 及官方技能按当前 CLI 帮助更新；不恢复已删协作 profile、Ponytail/Superpowers、自定义技能或遗留 OpenClaw 服务。
- 本机仅保留瑞幸、小电拼自定义 skill 及 DJI MCP；官方 Hermes/Lark 技能保留。名字含 openclaw 的现用飞书 stream 插件或历史目录不等于废弃服务，不得仅凭名字删除。
- 保留 Edge 路由、登录 profile、消息插件和 tunnel。此安装基线的 browser.backend: 'off' 选择内置工具，并非禁用浏览器；升级后以新代码验证语义，不机械套用。禁止启动 Chrome/Chromium 或批准其调试提示。
- gateway 重启只调度一次，记录旧进程身份；校验 supervisor wrapper 与新 gateway 子进程的归属，绝不能把新进程当残留杀掉。失败先检查监督器、退出码和日志，禁止让恢复的原任务再执行同一重启。
- 不自动恢复已取消任务；恢复标记仅用于重启后确实未完成的工作，并核验幂等状态。清理标记必须有当前 PID、commit 和健康证据，保留原始升级回执；另写恢复结果，不篡改历史失败为成功。

## 升级后验收

1. 核对新进程实际加载 commit、CLI 版本、鉴权可用性。仅默认配置正确不算所有会话生效；核对会话覆盖，不擅改模型、推理强度、fast、压缩或 idle reset。
2. 按 workspace/docs/MESSAGING.md 检查飞书两账号、同卡增量进度、reaction 终态、引用群内直回，以及微信确认、合并消息、清 typing、瑞幸二维码和状态投递。
3. 检查 API 健康与实际路由、cron 定义/调度器/最近结果；移动端发现地址必须从设备网络可达，不能把 loopback 或失效 tunnel 广播为健康地址。
4. 检查 /update 指令分发、CLI 更新、监督器重启和失败回执路径。先运行当前代码存在的相关测试，不为验收无限触发真实升级；未做端到端 /update 就明确标为未验证。
5. 相关测试通过、必要健康证据齐全即可结束；有活动任务不为刷新提示词重启。出现缺陷报告影响与最小修复方案，不承诺“以后绝不会失败”。

## 恢复存档边界

恢复仓库中的 runtime patch 仅适用各自标注的测试基线；新版本必须先验证兼容性。规则文件在 rules/ 单独维护，可独立恢复，不需要重新套用运行时补丁。私人 USER.md、MEMORY.md、会话、凭据和订单不得上传 GitHub。
