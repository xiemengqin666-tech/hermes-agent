# 瑞幸订单下单与状态盯单实战要点（课堂内复用）

## 关键参数坑位
- Luckin MCP 的部分接口参数区分大小写。
  - 正确：`deptId`
  - 错误示例：`deptid`
- 产品匹配与下单通常使用：`产品ID:SKU[:数量]`。

## 下单后立即校验
- 创建订单后，立刻查一次 `queryOrderDetailInfo`。
- 若 `orderStatusName == 待付款` 且 `needPay=true`，进入支付流程。
- 支付二维码优先使用 `payOrderQrCodeUrl`，回传图片并用于扫码支付。

## 微信投递与盯单
- 微信场景建议直接给 `weixin:<chat_id>`（如 `weixin:o9...@im.wechat`）而非默认频道。
- 盯单脚本建议 5~10 秒拉一次（本项目偏好 10 秒）并只在状态发生变化时通知。
- 若你看到重复推送/日志重叠，先确认同一 `orderId` 是否启动了多个 watcher；必要时先停旧进程后重启。

## 取餐阶段输出标准（Pigger 流）
- 可取餐/待取餐等到达时，消息里**同时**包含：
  - 取餐码（数字）
  - 取餐二维码（媒体卡片）
- 只发数字码不算完成。

## 小提醒
- `takeMealCodeInfo.code` 常见在支付前是 `生成中`，可继续盯单。
